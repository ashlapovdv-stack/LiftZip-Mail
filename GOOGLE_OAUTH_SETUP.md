# Подключение Google для сборки «Почта» 0.5.0

Код входа через Google включён. Реальный вход требует регистрации приложения в Google Cloud владельцем проекта и согласия владельца Gmail. Регистрация не выполнена автоматически: доступ к Google Cloud этого проекта не предоставлен.

## Данные готового Android-клиента

- Package name: `ru.liftzip.mail`
- SHA-1 сертификата текущей тестовой сборки: `52:A6:61:E2:59:E2:35:0E:86:A9:54:C8:A6:ED:41:CF:F5:7A:FE:7C`
- SHA-256 того же сертификата: `7F:4B:D2:91:A1:5D:84:1A:98:B9:A9:F5:F6:68:86:96:9E:B0:FF:B9:C1:65:9F:4D:96:E7:04:49:30:15:52:C1`
- Scope для IMAP/SMTP OAuth: `https://mail.google.com/`
- Тестовая подпись совпадает с ранее установленными сборками; APK можно обновить поверх.

## Регистрация владельцем

1. Открыть свой проект в [Google Cloud Console](https://console.cloud.google.com/) или создать отдельный проект для «Почты».
2. В Google Auth Platform заполнить сведения приложения и контакт владельца. Указать действительные страницы проекта и конфиденциальности, если их требует консоль.
3. В Clients создать OAuth client типа **Android** с package name и SHA-1 выше. В этой реализации нет собственного сервера, обмена server auth code или встроенного client secret. Android-привязка определяется именем пакета и подписью.
4. В Audience для личной проверки использовать тестовый режим и добавить Gmail владельца в Test users. В Data access добавить почтовый scope выше и проверить требования консоли к этому ограниченному scope. Для распространения другим пользователям может потребоваться проверка Google; тестовая регистрация не равнозначна публичному допуску.
5. На телефоне открыть **Настройки → Добавить ящик → Gmail → Через Google**, ввести точный адрес Google-аккаунта, присутствующего на устройстве, и подтвердить разрешение. Для уже подключённого ящика открыть его настройки и повторить вход.
6. Проверить получение, обновление токена и отправку между собственными тестовыми ящиками. Приложение проверяет IMAP и SMTP без отправки при подключении; само письмо отправляется только по кнопке «Отправить».

Изменение регистрации Android-клиента обычно не требует встраивать секрет в APK. Если Google сообщает об ошибке конфигурации, проверить точное совпадение пакета, сертификата установленного APK и выбранного Google Cloud проекта. Не использовать OAuth client от подключённого к ChatGPT Google Диска: это другое приложение.

До регистрации остаётся вариант **«Пароль приложения»**, если он доступен конкретному Google-аккаунту. На устройствах без Google Play services вход через AuthorizationClient недоступен.

## Поведение в приложении

AuthorizationClient получает и обновляет access token через Google Play services. Приложение хранит только признак выбранного способа входа; пароль Google и refresh token не сохраняются. Токен используется только с заранее разрешёнными адресами Gmail и TLS-портами, через XOAUTH2. При отказе токена локальный кэш токена очищается, затем выполняется одна повторная авторизация. Если требуется согласие пользователя, очередь переходит в состояние «Нужен повторный вход» до открытия настроек ящика. Удаление Google-ящика вызывает отзыв разрешения; при недоступной сети показывается инструкция отозвать его в Google-аккаунте.

Текущая сборка подписана стандартным тестовым ключом. Для публичного выпуска нужен собственный закрытый ключ и отдельная корректная регистрация его отпечатка. Такой ключ нельзя помещать в репозиторий или архив исходников.
