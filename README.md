# Lift-Zip Почта для Android — тестовая сборка 0.3.2

Нативный клиент на Kotlin и Jetpack Compose. Приложение подключается к почтовым серверам непосредственно с телефона. Промежуточный сервер приложения и размещение на REG.RU «Хост-0» для этой версии не требуются.

## Начать проверку

1. Установите `LiftZip-Mail-0.3.2-debug.apk` на Android 8.0 или новее. Версии 0.1–0.3.1 можно обновить поверх: сохранены идентификатор приложения, тестовая подпись и формат базы. Не удаляйте старое приложение перед обновлением.
2. При первом открытии выберите **«Подключить почту»**, укажите сервис, название ящика, полный адрес и подходящий пароль. Деморежим и вымышленные письма удалены из приложения.
3. Кнопка **«Проверить и подключить»** проверяет авторизацию IMAP и SMTP без отправки писем. Затем загружаются входящие.
4. Откройте **«Настройки → Загрузить всю историю»**. Выберите все или отдельные ящики и запустите автоматическую загрузку. Каждый успешно полученный текст сохраняется сразу; загрузку можно приостановить и продолжить. Вложения скачиваются по запросу.
5. Для проверки доставки отправьте письмо между двумя своими тестовыми ящиками и проверьте получение. Реальная отправка выполняется только по нажатию **«Отправить»**.

APK подписан отладочным ключом и предназначен для проверки, а не для публикации в магазине. При установке из файла Android может запросить разрешение устанавливать приложения для выбранного файлового менеджера или браузера.

Результаты проверки этой версии и контрольные суммы: [BUILD_CHECKS.md](BUILD_CHECKS.md). Проверка новых экранов на телефоне остаётся отдельным этапом.

## Подключение ящиков

| Сервис | IMAP, TLS | SMTP, TLS | Вход |
| --- | --- | --- | --- |
| Почта на хостинге REG.RU | mail.hosting.reg.ru:993 | mail.hosting.reg.ru:465 | Полный email и пароль ящика |
| Mail.ru | imap.mail.ru:993 | smtp.mail.ru:465 | Пароль для внешнего почтового приложения |
| Яндекс | imap.yandex.ru:993 | smtp.yandex.ru:465 | Пароль приложения и разрешённый IMAP |
| Gmail | imap.gmail.com:993 | smtp.gmail.com:465 | Пароль приложения Google, если он доступен аккаунту |
| Свой сервер | Задаётся вручную | Задаётся вручную | Логин и пароль, заданные администратором |

Сервис REG.RU имеет несколько почтовых продуктов. Предустановленные параметры относятся к **почте на виртуальном хостинге**. Для другого продукта используйте параметры из его панели управления и измените их в «Настройках серверов».

В настройках можно выбрать обязательный STARTTLS, обычно IMAP 143 и SMTP 587. Не поддерживаются незашифрованные соединения и отключение проверки сертификата.

Для Gmail основной пароль Google не подходит. Доступность паролей приложений зависит от двухэтапной проверки, типа аккаунта и ограничений администратора. Google OAuth в текущую сборку **не включён**. Для аккаунтов без паролей приложений подключение Gmail пока недоступно; поддержка OAuth запланирована отдельно и требует регистрации приложения в Google Cloud.

## Что реализовано

Новое в 0.3.2:

- История сначала сохраняет заголовки оставшихся писем, затем их тексты. Ошибка чтения одного текста не удерживает всю следующую страницу.
- Каждый текст сохраняется перед запросом следующего. Если соединение оборвалось или задание остановлено Android, успешно сохранённые тексты не теряются и не скачиваются заново.
- Чтение тела проверяет общий бюджет времени и отмену внутри MIME-обхода и чтения потока; сетевой таймаут одного чтения для истории — 10 секунд. Это не гарантия точной длительности на любом провайдере.
- Проблемный текст повторяется после остальных, максимум две попытки за запуск. После двух ошибок результат отмечается как частичный с темой письма, UID и причиной. Письмо остаётся в списке; можно повторить только неполученные тексты.
- Экран сверяет состояние с WorkManager, показывает этап, текущий UID и время последнего сохранения. При остановке либо отсутствии активности дольше 90 секунд доступен безопасный перезапуск продолжения.

Реализовано в 0.3.1:

- Нижние подписи однострочные: «Непроч.» и «Отправл.». Полные названия доступны средствам доступности.
- Управление полной загрузкой истории перенесено в настройки; в списке писем нет кнопок загрузки истории.
- У каждого ящика в боковом меню есть переключатель синхронизации. Выключение сохраняет пароль, настройки, письма и черновики; убирает ящик из общих разделов и отключает его опрос и уведомления. Сохранённые письма можно открыть, выбрав этот ящик отдельно. Несохранённый текст и вложения потребуют включения ящика. Отправка из выключенного ящика недоступна; отправитель по умолчанию временно выбирается из включённых.
- Обычная проверка получает статусы писем и заголовки новых без скачивания полных текстов. Уже известные заголовки повторно не запрашиваются. Текст новых писем загружается при открытии либо при полной загрузке истории; история сохраняет тексты небольшими порциями и вложения по запросу. В настройках видны время и длительность последней попытки проверки.
- Сетевые запросы проверки и истории выполняются вне общей блокировки данных. История не задерживает ручное обновление и чтение сохранённых писем. До трёх ящиков проверяются параллельно, результат каждого появляется сразу. Ответы старых запросов после выключения, удаления или изменения ящика отбрасываются; параллельная загрузка не откатывает успешно изменённые статусы и не обрезает историю.
- Обновление свайпом показывает тонкую полосу под верхней панелью; индикатор не перекрывает строки писем. Ручная проверка относится к выбранному ящику, в режиме «Все ящики» — ко всем включённым.

Реализовано в 0.3:

- Для больших ящиков список держит короткие превью, полные тексты остаются в базе и читаются при открытии. Полнотекстовый поиск выполняется по сохранённой базе в фоне; смена статуса не перезаписывает тело письма превью.

- Позиция прокрутки сохраняется отдельно для каждого ящика и раздела при переходах в письмо, редактор и настройки. Если список находится точно вверху, новые письма сразу становятся видны; при просмотре старых писем сохраняется место.
- Внизу рядом с «Входящими» добавлен раздел **«Непрочитанные»**. Он учитывает выбранный ящик, а в режиме всех ящиков объединяет их непрочитанную почту. Запрашиваются все непрочитанные с сервера, включая старые письма за пределами первых 100. Для ещё не загруженных писем сначала сохраняются заголовки, текст загружается при открытии или при полной загрузке истории.
- Непрочитанные письма выделяются фоном, полосой слева, жирным текстом и подписью «Не прочитано».
- Долгое нажатие выделяет письмо. Можно выбрать несколько или все загруженные письма текущего списка и отметить их прочитанными или непрочитанными. Успешные изменения подтверждаются сервером; ошибки показываются, неуспешные письма остаются выделенными.
- Обновление свайпом вниз, немедленная проверка при возвращении в приложение, интервалы проверки открытого приложения 1/5/15/30/60 минут. Для фона: 15/30/60/120 минут или отключение.
- В настройках у ящиков отображаются последняя успешная проверка и ошибка последней попытки. Это помогает отличить задержку запуска от ошибки соединения.
- Редактирование подключённого ящика с проверкой IMAP/SMTP перед сохранением. Пустой новый пароль сохраняет действующий. При смене параметров IMAP-подключения или логина входящий кэш загружается заново; черновики и отправленные сохраняются. Другой email добавляется отдельным ящиком.
- Автоматическая загрузка всей истории **INBOX** выбранных ящиков выполняется фоновыми заданиями небольшими порциями с сохранением прогресса. При сбое сети повторяется автоматически; есть пауза и продолжение. Старая история не создаёт новых почтовых уведомлений.
- Уведомление о новых письмах сверяется с их фактическим статусом после всех способов синхронизации и после смены статуса. После прочтения последнего уведомлённого письма уведомление убирается. Прочтение в другом клиенте учитывается при следующем обновлении.
- Постоянная декоративная точка убрана с иконки. Системный индикатор уведомлений управляется Android и настройками лаунчера.

Сохраняются функции предыдущей версии:

- Несколько отдельных ящиков и общие входящие с указанием ящика у каждого письма.
- Чтение писем, поиск по загруженному содержимому, отметки прочтения и избранного.
- Постраничная загрузка более старых входящих с сохранением загруженной истории при обновлении; на сервере ничего не удаляется.
- Отправка текстовых писем, ответ и пересылка с автоматическим добавлением вложений. Для черновиков пересылки создаются собственные копии вложений в закрытом каталоге приложения.
- Нажатие на входящее вложение открывает просмотр; отдельный значок загрузки сохраняет копию в выбранное место.
- Встроенный просмотр PDF по страницам и изображений с увеличением жестом. Остальные форматы открываются установленной на телефоне программой с временным разрешением чтения конкретного файла.
- Декодирование имён получателей, включая заголовки, уже сохранённые версией 0.1.
- Сворачивание распознанного цитируемого текста под кнопкой **«…»**. Полный текст письма сохраняется и доступен при раскрытии. Это цитата внутри письма, а не серверная группировка отдельных писем в цепочку.
- Редактор тела письма на всю ширину с небольшими внутренними отступами; сервисные сообщения расположены выше системной навигации и клавиатуры.
- **Настройки → Отправитель по умолчанию**: выбранный ящик используется для новых писем и пересылки. Ответ отправляется с того ящика, на который поступило письмо. В редакторе можно изменить отправителя для отдельного письма.
- Сохранение и повторное редактирование локальных черновиков. Текст редактора переживает поворот экрана.
- Предустановленные серверы REG.RU, Mail.ru, Яндекса и Gmail, ручные настройки другого сервера.
- Шифрование паролей AES-GCM с ключом в Android Keystore. К email-содержимому не применялось отдельное шифрование БД: кэш находится в закрытом каталоге приложения.
- Проверка TLS-сертификатов, отсутствие внешних аналитических сервисов и отключённые резервное копирование и перенос данных приложения.
- Периодическая фоновая проверка и уведомления при выданном системном разрешении.

## Текущие ограничения

- Проверять сначала на собственных тестовых ящиках. Сборка и модульные тесты не заменяют проверку на телефоне и реальных провайдерах.
- Сначала загружаются заголовки **100 последних входящих**. Всю историю и тексты можно сохранить через **«Настройки → Загрузить всю историю»**. При обычном обновлении запрашиваются письма начиная с самого старого загруженного UID; новые письма не вытесняют загруженную историю. Изменение UIDVALIDITY безопасно сбрасывает устаревший локальный кэш этого ящика.
- Произвольные серверные папки пока не загружаются. Поиск работает по загруженному локальному кэшу.
- Черновики и копии отправленных из клиента **локальные**. Они не синхронизируются между устройствами и не добавляются в серверную папку «Отправленные». Само письмо передаётся через SMTP.
- Автоматическая пересылка ограничена теми же размерами, что и новая отправка. Если файл недоступен или превышает лимит, подготовка пересылки завершается сообщением об ошибке; вложения не пропускаются молча.
- Сворачивание цитат использует признаки известных почтовых клиентов. Неоднозначный текст и ответы внутри цитаты показываются полностью.
- Файлы для отправки: до 20 МБ каждый и 25 МБ суммарно, скачивание: до 25 МБ. Лимит провайдера с учётом кодирования может быть меньше.
- Отображается безопасная текстовая версия письма. Скрипты, HTML-интерфейс и удалённые картинки не исполняются и не загружаются.
- Для отметок «прочитано» и «избранное» у серверных писем требуется соединение. Очередь отложенных изменений пока не реализована.
- Сохранение черновика выполняется кнопкой «Сохранить» или при возврате из редактора. Автосохранение при аварийном завершении процесса не реализовано.
- Для открытого приложения настраивается опрос от 1 минуты; при возвращении в него проверка запускается сразу. Фоновый интервал WorkManager настраивается от 15 минут, Android может откладывать выполнение при энергосбережении. Это **не мгновенные push-уведомления**. Настройка более короткого опроса открытого приложения не отменяет фоновые ограничения Android.
- Первая успешная загрузка не уведомляет обо всех старых письмах. Новое письмо после пустого ящика учитывается.
- Отправка не повторяется автоматически. Если SMTP-сервер не подтвердил результат, приложение сохраняет черновик с неопределённым статусом: проверьте фактическую доставку перед повтором.
- Переключатель выключает синхронизацию без удаления данных. Только кнопка **«Удалить ящик»** удаляет его локальный кэш и черновики. Письма и папки на сервере сохраняются. Повторное подключение необходимо после удаления приложения или переноса на другой телефон.

Сотрудник сможет установить приложение на своём устройстве и подключить свои ящики. Обмен данными между установками и общая учётная запись сервиса в этой архитектуре отсутствуют.

## Сборка из исходников

Нужны Android Studio с JDK 17, Android SDK 36, Build Tools 35.0.0 и доступ к Google Maven и Maven Central.

Откройте эту папку как проект Android Studio и дождитесь синхронизации Gradle. Укажите путь к SDK через Android Studio или переменную окружения `ANDROID_HOME`.

Windows:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

Linux/macOS:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Репозиторий: https://github.com/ashlapovdv-stack/LiftZip-Mail. GitHub Actions запускает модульные тесты и сборку APK при изменениях ветки `main`; APK сохраняется как артефакт `LiftZip-Mail-debug`. Новые установочные файлы и архивы исходников также сохраняются в согласованной папке LiftZip-Mail на Google Диске.

Версии зафиксированы: AGP 8.13.2, Gradle 8.13, Kotlin 2.2.21, Compose BOM 2025.12.00. Включён только публичный стандартный ключ тестовой сборки. Для релиза потребуется отдельный закрытый ключ подписи; не заменяйте им тестовый ключ и не размещайте его в исходниках.
